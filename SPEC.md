**Версия:** 1.0 · 2026-10-11
**Заказчик:** Владилен Минин
**Исполнитель:** Claude Code (рекомендуемая модель — Opus 5.5)

## 0. Как пользоваться этим документом

1. Создай пустую папку `~/reels-studio` и положи в неё этот файл как `SPEC.md`.
2. Открой в этой папке Claude Code.
3. Вставь стартовое сообщение из раздела 14.

Claude Code выполняет фазы по порядку. После каждой фазы он отчитывается и ждёт подтверждения, кроме случаев, где в фазе прямо сказано «без остановки».

## 1. Цель

Локальный проект на Mac, в котором Claude Code монтирует **сырые вертикальные рилсы с говорящей головой** (русская речь, тематика AI и фронтенд) в готовые ролики.

Что входит в монтаж:

- вырезка пауз, оговорок и дублей;
- хук на первые 3 секунды и драматургия;
- моушн-графика, привязанная к словам;
- субтитры;
- самопроверка по кадрам;
- экспорт под Instagram Reels.

Сценарий использования одной командой:

```
/reel inbox/raw.mov — про агентов, хук про 10 часов
```

### Критерии успеха MVP

- Сырой рилс 30–90 с проходит весь пайплайн без ручного кода.
- Человек участвует только в трёх точках: выбор хука и плана графики, правки по превью, проверка звука.
- Итоговый файл проходит автоматическую проверку кодировки и безопасных зон (раздел 9).
- Правки пользователя накапливаются в `lessons.md` и учитываются в следующих прогонах.

| Платформа | macOS, Homebrew | Машина заказчика |
| Язык речи и субтитров | Русский | Требует русификации (фаза 3) |
| Режим вывода по умолчанию | `kit`: чистый монтаж + клипы графики + субтитры + превью | Контроль у человека. Режим `full` — готовый MP4 |

## 3. Архитектура

### 3.1. Принцип

Claude не монтирует по таймлайну. Он превращает видео в данные, принимает решения текстом, а инструменты исполняют.

- **Уши (транскрипт).** Время каждого слова — это и есть таймлайн для Claude.
- **Ножницы (EDL).** Список склеек в секундах исходника. Режет ffmpeg. Исходник никогда не меняется.
- **Графика.** HTML-страницы, где каждый стиль — чистая функция времени `seek(t)`. Chrome/Playwright снимает кадры.
- **Глаза.** Контакт-листы кадров. Claude смотрит и правит.
- **Ушей нет.** Финальный звук проверяет человек. Claude обязан прямо об этом говорить и никогда не утверждать, что «послушал».

### 3.2. Конвейер одного рилса

```
inbox/raw.mov
  └─ S0 приём: проект, копия исходника, ffprobe, бриф
     └─ S1 транскрипция: ElevenLabs (ru) → нормализация → transcript.words.json
        └─ S2 чистка: cut-silences + cut-mistakes(RU) + ручной проход → EDL → clean.mp4 + перетаймленный транскрипт
           └─ S3 драматургия: short-form-edit → DESIGN.md, OPEN-LOOPS.json, 3 хука, план графики
              ── ГЕЙТ B (обязательно): человек выбирает хук и утверждает план ──
              └─ S4 графика: motion-broll и/или talking-head-recut, бренд, кириллица
                 └─ S5 субтитры: embedded-captions (по умолчанию стиль anchor rail)
                    └─ S6 самопроверка: контакт-листы, чек-лист, до 3 итераций
                       └─ S7 сборка: превью → ГЕЙТ C (правки человека) → экспорт + проверки
                          └─ S8 уроки: правки → lessons.md → предложения к правилам скилла
```

ГЕЙТ A (показать список вырезанного) по умолчанию выключен: Claude вырезает сам и кладёт отчёт `CUTS.md`. Включается флагом `--review-cuts`.

## 6. Фазы реализации

Общие правила для всех фаз:

- Отчитываться коротко: что сделано, что проверено, что не удалось.
- Не помечать фазу выполненной, если её проверки не прошли.
- Не коммитить видео, рендеры и `.env`.
- Коммит после каждой фазы с понятным сообщением.

### Фаза 0. Окружение

**Задачи:**

1. Проверить и при необходимости установить через Homebrew: Node ≥ 22, npm, git, ffmpeg + ffprobe (с энкодером `prores_ks`), Python 3, `uv` (даёт `uvx` для запасной транскрипции WhisperX в embedded-captions), Google Chrome.
2. Убедиться, что `ffmpeg -encoders | grep prores_ks` что-то находит (нужно motion-broll для прозрачных `.mov`).
3. Убедиться, что в системе есть русский голос для `say` (`say -v '?' | grep ru_RU`). Он нужен для синтетической фикстуры.

**Готово, если:** все версии выведены в отчёт, недостающее установлено или явно перечислено для ручной установки.

### Фаза 1. Шасси

**Задачи:**

1. Клонировать `hyperframes-student-kit` в текущую папку, сохранив `SPEC.md`. Удалить его `.git`, сделать `git init`.
2. `npm ci` → `npm run setup` → `npm test`.
3. `npm run demo`, затем в `video-projects/demo`: `npx hyperframes lint` и `npx hyperframes render --quality draft --output renders/demo.mp4`.
4. Создать `.gitignore`-дополнения: `.env`, `inbox/*`, `video-projects/*/assets/`, `video-projects/*/renders/`, `video-projects/*/motion/work/`, `refs/*.mp4`, `refs/*.mov`. Не игнорировать `.md`, `.json` и HTML-композиции.

**Готово, если:** `npm test` зелёный, `renders/demo.mp4` существует и ffprobe читает его без ошибок.

### Фаза 2. Дополнительные скиллы

**Задачи:**

1. Установить скиллы из раздела 5 в `.claude/skills/`. Дубли шасси (`hyperframes`, `hyperframes-cli`, `gsap`, `hyperframes-registry`, `website-to-hyperframes`) **не перезаписывать**: шасси закрепляет их версии в `skills-lock.json`.
2. **Совместимость HyperFrames.** Шасси закрепляет `hyperframes@0.7.109`. Проверить, какую версию CLI ожидают `embedded-captions` и `talking-head-recut`. Решение по правилу:
   - если работают на закреплённой — ничего не менять;
   - если нужна новее — поднять `hyperframes` в `package.json`, прогнать `npm test` и демо-рендер. Если шасси сломалось — откатить и запускать эти два скилла через отдельную подпапку-проект со своей версией CLI. Решение записать в `vendor/SOURCES.md`.
3. Для `embedded-captions` поставить зависимости, которые он требует (sharp, puppeteer, gsap в проект субтитров), по его `SKILL.md`.
4. Для `motion-broll` выполнить его `scripts/setup.sh` в тестовой папке и проверить запуск движка.
5. `object-separation` (SAM 2) поставить, но пометить в `CLAUDE.md` как опциональный и тяжёлый. В MVP-прогонах не вызывать без запроса.
6. Создать `vendor/SOURCES.md`.
7. Прогнать `npm run check` и `npm run check:skills` (или `npm run sync:skills`, если шасси требует синхронизации `.agents/skills`).

**Готово, если:** все скиллы видны в Claude Code (`/` показывает их), имена не конфликтуют, `npm test` по-прежнему зелёный.

### Фаза 3. Русификация

Это самая важная фаза для качества. Шасси написано под английскую речь.

**3.1. Транскрипция**

- Проверить `scripts/transcribe-elevenlabs.mjs`. Добавить параметр языка (`language_code` для русского — сверить точное значение с актуальной документацией Scribe API) и включённые пословные таймкоды.
- Кэш: если для исходника с тем же SHA-256 уже есть транскрипт, повторно не платить.

**3.2. Нормализация** — `scripts/ru/normalize-transcript.mjs`

- Вход: ответ ElevenLabs.
- Выход: формат шасси — `{ text, audio_duration_secs, words: [{ text, start, end }] }`, время в секундах исходника. Длительность взять из ffprobe.
- Для сравнения слов (поиск дублей) использовать отдельный ключ: нижний регистр, `ё → е`, без пунктуации. Отображаемый текст не трогать.
- Отбрасывать служебные токены (пробелы, аудиособытия), если провайдер их отдаёт.

**3.3. Оговорки и дубли**

- В `.claude/skills/cut-mistakes/scripts/find-cut-candidates.mjs` стоп-слова захардкожены по-английски (`… like um uh`). Вынести список в конфиг и добавить русский из `scripts/ru/ru-fillers.json`.
- Минимальный состав `ru-fillers.json`:
  - **стоп-слова:** и, а, но, в, на, с, по, к, у, о, из, за, что, это, как, так, же, ли, бы, не, я, ты, мы, вы, он, она, они;
  - **паразиты:** э, ээ, эм, мм, ну, вот, типа, короче, как бы, в общем, значит, собственно, скажем так;
  - **маркеры перезаписи:** «ещё раз», «заново», «стоп», «сначала», «не так», «давай ещё», «так, ещё раз».
- Маркер перезаписи повышает вероятность, что предыдущий незаконченный фрагмент — брошенный дубль.
- Сохранить обязательное правило шасси: **после автопоиска Claude читает весь транскрипт вручную**. Нулевой отчёт детектора не значит, что дублей нет.

**3.4. Шрифты и текст**

- Использовать только шрифты с кириллицей (Inter — с кириллицей, Geist — проверить покрытие в установленной версии).
- Добавить проверку: для всех символов в субтитрах и графике шрифт должен содержать глифы. Если глифа нет — ошибка, а не тихая подмена.
- Переносы строк в субтитрах: русские слова длиннее английских. Не более ~22 символов в строке, максимум 2 строки, без переносов внутри слов.

**3.5. Адаптер для motion-broll** — `scripts/ru/words-to-srt.mjs`

motion-broll по умолчанию ждёт SRT и оценивает время слов с точностью ±0,2 с. Подавать ему наш пословный транскрипт: сгенерировать SRT из точных слов. Если его `scripts/words.py` можно научить читать JSON — сделать так и записать изменение в `SOURCES.md`.

**3.6. Фикстура** — `scripts/ru/make-ru-fixture.sh`

Синтетический рилс без реальной съёмки:

- macOS `say` с русским голосом произносит текст с паузами, «э-э» и одним явным дублем («…агенты экономят время. Стоп, ещё раз. Агенты экономят часы…»);
- ffmpeg собирает 1080×1920, 30 fps, однотонный фон плюс эта дорожка;
- рядом кладётся эталон: какие фрагменты должны быть вырезаны.

**Тесты (`node --test`):**

- нормализация русского транскрипта (ё/е, пунктуация, длительность);
- детектор находит паразиты и дубль в фикстуре;
- `words-to-srt` даёт валидный SRT;
- проверка глифов падает на символе вне шрифта.

**Готово, если:** все тесты зелёные, и на фикстуре S1–S2 вырезают паузы, «э-э» и дубль (сверка с эталоном).

### Фаза 4. Личный слой: оркестратор `vladilen-reels`

**Задачи:**

1. Написать `.claude/skills/vladilen-reels/SKILL.md` по спецификации раздела 7.
2. Создать `.claude/commands/reel.md`. Команда передаёт `$ARGUMENTS` (путь к файлу и бриф) скиллу `vladilen-reels`.
3. Создать заготовки:
   - `brand/brand.md` с полями-заглушками: акцентный цвет, фон, шрифт заголовков, шрифт субтитров, стиль субтитров, CTA по умолчанию, логотип;
   - `refs/NOTES.md`;
   - `lessons.md` (формат в разделе 10).
4. Перенести в `vladilen-reels/references/` адаптированные чек-листы из `whaleyxbt/claude-motion`. Всё, что про `npm run sheet` Remotion, заменить на команды HyperFrames.
5. Дописать в `CLAUDE.md` раздел «Reels Studio» (раздел 8.1) и синхронизировать `AGENTS.md`.
6. Создать `.claude/settings.json` с разрешениями на частые безопасные команды: `ffmpeg`, `ffprobe`, `node scripts/*`, `npx hyperframes *`, `npm run *`, `python3 .claude/skills/*`. **Не разрешать** удаление файлов вне `video-projects/*/renders` и сетевые вызовы, кроме ElevenLabs.

**Готово, если:** `/reel` виден в Claude Code, а сухой прогон на фикстуре (раздел 6, фаза 5) доходит до ГЕЙТА B.

### Фаза 5. Сквозной прогон на фикстуре

Без остановок до ГЕЙТА B. На гейте показать план и остановиться.

- Прогнать `/reel` на синтетической фикстуре в режиме `kit`, затем в режиме `full`.
- Проверить, что все артефакты из 7.3 созданы, а `check-reel.mjs` проходит.

**Готово, если:** оба режима отработали, отчёт о прогоне записан в `runs.log.jsonl`.

### Фаза 6. Тест на реальном рилсе

Заказчик кладёт реальный сырой рилс в `inbox/` и 2–5 эталонов в `refs/`, заполняет `brand/brand.md`.

- Полный прогон с участием человека на гейтах B и C.
- После прогона — S8 (уроки).

**Готово, если:** заказчик принимает результат или правки оформлены в `lessons.md`. Цель: 3–5 калибровочных прогонов.

### Фаза 7 (опционально). Higgsfield B-roll

Только по явной просьбе заказчика.

- Сверить актуальные возможности Higgsfield API или CLI по документации: модели, вертикальный формат, цена.

- **Перед каждой платной генерацией** показывать промпт и ожидаемую стоимость и ждать «да».

## 7. Спецификация оркестратора `vladilen-reels`

### 7.1. Вызов

```
/reel <путь к файлу> [— бриф одной строкой] [--mode kit|full] [--review-cuts] [--density light|medium|heavy]
```

По умолчанию: `--mode kit`, плотность `medium`.

### 7.2. Стадии

| Стадия | Делает | На выходе | Остановка |
|---|---|---|---|
| **S0 Приём** | `npm run new-video -- <YYYY-MM-DD-slug>`, копирует исходник в `assets/raw.*` (оригинал не трогает), ffprobe, читает `brand/brand.md`, `lessons.md`, `refs/NOTES.md` | `PROBE.json`, `BRIEF.md` | Нет |
| **S1 Транскрипция** | ElevenLabs (ru) с кэшем → нормализация. Санити-проверка: текст должен читаться как русский | `transcript.raw.json`, `transcript.words.json` | Только если транскрипт — мусор |
| **S2 Чистка** | `cut-silences` → `cut-mistakes` (RU) → ручное чтение всего транскрипта → EDL с причинами → рендер `clean.mp4` → перетайминг слов по EDL | `EDL.json`, `CUTS.md`, `clean.mp4`, `transcript.clean.json` | Только с `--review-cuts` |
| **S3 Драматургия** | `short-form-edit`: вопрос «убеждают ли первые 3 секунды досмотреть», открытые петли, 3 разных варианта первых 3 секунд, план графики (таймкод, тип: полноэкранная врезка / панель рядом / карточка поверх / ничего, причина), CTA | `DESIGN.md`, `OPEN-LOOPS.json`, `PLAN.md` | **ГЕЙТ B, всегда** |
| **S4 Графика** | По утверждённому плану: `motion-broll` (клипы, привязанные к словам) и/или `talking-head-recut` (карточки поверх). Учесть `motion-principles` и `brand.md`. Только реальные цифры и факты из речи или от заказчика | `broll/*.mp4`, `broll/*.mov` (ProRes 4444 с альфой), `compositions/` | Нет |
| **S5 Субтитры** | `embedded-captions` по `transcript.clean.json` (наш транскрипт, без повторной транскрипции). Стиль из `brand.md`, по умолчанию anchor rail. Правила переноса из 3.4 | `captions/`, `captions.srt` | Нет |
| **S6 Самопроверка** | Черновой рендер → контакт-листы на каждом событии плана и каждые 2 с → чек-лист (7.4) → правки. Максимум 3 итерации, затем отчёт об остатках | `review/sheet-*.png`, `REVIEW.md` | Нет |
| **S7 Сборка** | Превью в половинном разрешении → **ГЕЙТ C**: заказчик смотрит (`npx hyperframes preview` или файл) и даёт правки → применить → финальный экспорт (раздел 9) → `check-reel.mjs` | `renders/preview.mp4`, итоговые файлы режима | **ГЕЙТ C, всегда** |
| **S8 Уроки** | Записать правки заказчика в `lessons.md`, предложить изменения правил скилла | Обновлённый `lessons.md` | Изменения правил — только после «да» |

### 7.3. Артефакты одного рилса

```
video-projects/2026-10-12-agents-10h/
├── assets/raw.mov                # копия исходника (не коммитится)
├── PROBE.json  BRIEF.md  STATUS.md
├── transcript.raw.json  transcript.words.json  transcript.clean.json
├── EDL.json  CUTS.md
├── DESIGN.md  OPEN-LOOPS.json  PLAN.md
├── compositions/  broll/  captions/
├── review/  REVIEW.md
└── renders/
    ├── clean.mp4                 # только склейки, без графики
    ├── preview.mp4
    ├── final.mp4                 # режим full
    └── kit/                      # режим kit
        ├── clean.mp4
        ├── broll/<NN>-<slug>_<таймкод>.mov|mp4
        ├── captions.mov          # субтитры с альфой
        ├── captions.srt
        ├── TIMING.md             # каждый клип: in/out и фраза, которую он покрывает
        └── compare.html          # оригинал против версии с графикой
```

`STATUS.md` хранит текущую стадию и решения. Прерванный прогон продолжается с последней завершённой стадии, без повторных платных вызовов.

### 7.4. Чек-лист самопроверки (S6)

- **Безопасная зона:** весь значимый текст и логотипы — в пределах y 360–1420 px и не правее x 960 (правые 120 px заняты кнопками Instagram).
- Лицо спикера не перекрыто графикой, кроме запланированных полноэкранных врезок.
- Один фокус в кадре: две вещи не борются за внимание.
- Нет наложений текста при переходах.
- Субтитры читаются: контраст, размер, не больше 2 строк.
- Все глифы на месте, кириллица без подмен.
- Кадр 0 — содержательный (обложка рилса), а не чёрный.
- Хук понятен без звука.
- Ни одного выдуманного числа, факта или результата.
- Синхрон: событие графики попадает на своё слово (сверка с таймкодами, допуск ±2 кадра).

В отчёте Claude **обязан** написать: «Звук мной не прослушан: громкость, музыку и склейки по интонации проверь на слух».

### 7.5. Режимы вывода

- **`kit` (по умолчанию):** набор для монтажки — чистый монтаж, клипы графики (полноэкранные — MP4, панели — ProRes 4444 с альфой), субтитры (MOV с альфой + SRT), `TIMING.md` с таймкодами вставки, превью и `compare.html`. ProRes с альфой открывается в Premiere, Final Cut и DaVinci. Для CapCut проверить поддержку альфы и при необходимости отдать полноэкранные версии.
- **`full`:** один `final.mp4`, готовый к загрузке.

### 8.1. Раздел «Reels Studio» в `CLAUDE.md` (дописать)

## 9. Технические требования к выходу

| Параметр | Значение |
|---|---|
| Разрешение | 1080×1920 |
| FPS | Как у исходника (обычно 30). Без апсемплинга |
| Видео | H.264 High, `yuv420p`, limited range (`tv`), BT.709, CRF ≈ 18, `+faststart` |
| Аудио | AAC 48 кГц, ≈ 128–192 кбит/с. Если звука нет — тихая дорожка |
| Громкость | Интегральная около −14 LUFS (ffmpeg `loudnorm`, двухпроходный). Музыка под голосом заметно тише голоса |
| Безопасная зона | y 360–1420, правые 120 px пустые (по `reel-export`) |
| Длительность | Как получилась после монтажа. Без искусственного растягивания |

`scripts/ru/check-reel.mjs` проверяет через ffprobe кодек, профиль, `pix_fmt`, цветовое пространство, разрешение, fps, наличие аудио, громкость (через `ebur128`/`loudnorm` в режиме анализа) и пишет PASS/FAIL по каждому пункту. Безопасную зону проверяет S6 по контакт-листам.

## 10. `lessons.md` — как копится вкус

Формат записи:

## 2026-10-12 · agents-10h

## 13. Риски и ограничения

| Риск | Что делаем |
|---|---|
| Claude не слышит итоговый звук | Человек проверяет на слух. Обязательная фраза в отчёте |
| Детектор дублей слабее на русском | Русский конфиг (3.3) плюс обязательное ручное чтение транскрипта |

| Рендер медленный | Черновики в половинном разрешении, финал один раз после ГЕЙТА C |
| Повторные платные вызовы | Кэш транскрипта по SHA-256 исходника |
